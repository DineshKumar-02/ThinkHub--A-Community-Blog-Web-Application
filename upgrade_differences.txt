================================================================================
                    THINKHUB - BRANCH COMPARISON REPORT
                     Branch 'main' vs Branch 'upgrade'
================================================================================

This document details the modifications, improvements, new components, and overall
functional differences between the original 'main' branch and the enhanced 'upgrade' branch.

--------------------------------------------------------------------------------
1. ARCHITECTURAL & UI STYLE REVAMP
--------------------------------------------------------------------------------
* main branch:
  - Simple, basic styling with inline JavaScript CSS style objects.
  - Dominated by a solid purple theme (#6c63ff) with standard white containers.
  - Lacks styling animations, smooth transitions, and dark mode support.

* upgrade branch:
  - Implements a central, unified theme system in index.css with CSS Variables:
    * Light mode: Warm Cream & Soft Orange color palette.
    * Dark mode: Glassmorphic dark theme.
  - Supports dynamic theme toggle using a floating cartoon theme toggle button.
    Preference is persisted in the browser's `localStorage` ('theme') and synced
    to the DOM using the `dark-theme` class on the <html> element.
  - Adds micro-animations: scale-ups (`animate-scale`), fade-ins (`animate-fade`),
    and slide-ups (`animate-slide`).

--------------------------------------------------------------------------------
2. NEW REUSABLE FRONTEND COMPONENTS
--------------------------------------------------------------------------------
* Navbar.jsx (New)
  - Replaces the repetitive nav code that was duplicated on multiple pages.
  - Features:
    - Logo navigation and brand name.
    - Conditional search bar (integrates with search states on pages like Home).
    - Responsive categories dropdown menu which lists topics with emojis and routes
      the user to the corresponding topic page on selection.
    - Navigation links (Home, About, Contact).
    - Floating dark/light theme switch toggler.

* Footer.jsx (New)
  - A beautiful, cohesive glassmorphic footer component.
  - Multi-column layout containing:
    - ThinkHub brand branding and description.
    - Navigation links.
    - Reach Out contact redirect button.
    - Copyright information.

* BlurhashImage.jsx (New)
  - Integrates the `blurhash` library (added to dependencies in package.json) for 
    progressive image rendering.
  - How it works:
    1. Accepts a short string representation of a blurred image placeholder (hash).
    2. Decodes the hash into raw pixels (32x32 standard dimensions) using the
       `decode` library method, drawing it onto an absolute-positioned canvas.
    3. Triggers a CSS transition once the main <img> loads (`onLoad` fires),
       fading out the placeholder canvas and fading in the actual image.

--------------------------------------------------------------------------------
3. HOMEPAGE EXPERIENCE (Home.jsx)
--------------------------------------------------------------------------------
* main branch:
  - Homepage acted as a static landing page.
  - Displayed a grid of circular topic category links.
  - Had no feed to view actual posts directly.

* upgrade branch:
  - Homepage converted into a dynamic Community Stories Feed:
    - Fetches the 20 most recent posts from the backend server on mount.
    - Integrates with the global Navbar search query to filter blogs by title,
      content, or category.
    - Displays interactive filter chips (e.g. All, Tech, AI, Lifestyle, Finance)
      to quickly narrow down the feed by category.
    - Uses Flexbox cards (`flex-posts-container`) with custom slide animations.
    - Integrates a modal overlay, allowing users to read the full story context
      interactively without navigating away from the Home page.

--------------------------------------------------------------------------------
4. TOPICS PAGE & POSTS SUBMISSION (Topic.jsx)
--------------------------------------------------------------------------------
* main branch:
  - Used inline JS style blocks for rendering the topic posts grid.
  - Very basic modal overlay to read full posts.

* upgrade branch:
  - Glassmorphic card design (`glass-card`, `glass-card-hover`).
  - Improved form layout for submitting new posts (handles submission loading
    states (`submitting` state) to prevent duplicate submissions).
  - Modern grid design for cards with a footer containing date labels and the
    Delete button.
  - Premium modal view styling with detailed metadata (e.g., category and publish date).

--------------------------------------------------------------------------------
5. LOGIN & SIGNUP PAGES (Signup.jsx)
--------------------------------------------------------------------------------
* main branch:
  - Standard, simple signup form.

* upgrade branch:
  - Splitted into a dual-panel container (`auth-split-container`):
    - Left Panel: Quotes carousel (`BLOG_QUOTES`) displaying random quotes about
      writing and sharing knowledge, creating a professional reading atmosphere.
    - Right Panel: A centralized glassmorphic card for signup/login details.

--------------------------------------------------------------------------------
6. BACKEND API ROUTES
--------------------------------------------------------------------------------
* backend/routes/postRoute.js:
  - Added a new `GET /` endpoint:
    - Fetches up to 20 recent posts sorted in reverse chronological order:
      `Post.find().sort({ created_at: -1 }).limit(20)`
    - Powers the Home page community stories feed.

* backend/routes/userRoute.js:
  - Enhanced the passwordless registration/login workflow:
    - If a user submits credentials that already exist (both username and email match),
      the server logs them in successfully (returns status `200` with the user profile)
      rather than blocking the attempt with a "username already exists" error.
    - If a conflict is detected (i.e. username is taken by a different email, or
      email is taken by a different username), it keeps blocking with the
      appropriate error (e.g. `"already an message is there"` or `"Email already exists"`).
